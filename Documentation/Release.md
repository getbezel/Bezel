# Release acceptance

The project produces a universal macOS app with an embedded sandboxed FinderSync extension and an isolated charge-control executable. Local build success and deterministic tests do not establish full production acceptance. Preserve the original eleven-module requirements when evaluating this checklist.

## Current verification

- Debug build succeeds under Swift 6 against the installed macOS SDK.
- A universal Apple silicon/Intel Release archive succeeds with local ad-hoc signing. The current verification record must identify the exact source hashes and archive checked.
- The native dashboard launches; its sidebar sizing, search filtering, navigation, live HAL device/process discovery, camera-housing detection, Settings tabs, and successful shortcut registration were checked through the running app.
- Production clipboard store tests cover FIFO order, count/memory limits, queue retention after history eviction, stale-head consumption, and release of data.
- Production realtime renderer tests cover planar/interleaved streams, channel mirroring, hardware input exclusion, clipping/nonfinite samples, gain ramps, short/null buffers, format-change silence, and real stereo FFT frequency bands, including opposite-phase stereo.
- System tests cover bounded read-only archive inspection, tar.gz/RAR5/7z extraction, no-overwrite results, ZIP round trip, traversal/absolute path/link/device/duplicate/oversized archives, staging cleanup, Finder inspect/analyze/compress/extract request parsing, scan/inspection cancellation, allocated sizes, and monotonic countdown expiry. Pulse assertions are inspected through IOKit for the test's exact PID before/after expiry and restart, including explicit release. The RAR fixture's upstream revision and license are retained with the fixture.
- Automation tests cover literal subprocess arguments, both output streams, timeout/cancellation/output bounds, inherited-pipe deadlines/cancellation after the command exits, forced termination of an unresponsive command, Focus start/stop races and failed-ending recovery, menu visibility selection policy, and charge-response validation and serialization. Injected test workflows do not establish actual Do Not Disturb behavior.
- Media tests cover bounded, typed player replies; route/player matching; source-specific controls; disabled-by-default reads; late reply/consent rejection; and image decoding, CDN policy, HTTP/byte limits and request cancellation. They use injected players and local URLProtocol responses, without live Automation access or network requests.
- Native Release inspector checks passed for hidden/Unicode/space filenames, Unicode filtering, extraction through the destination picker with exact output-content verification, and unsafe-path warnings with extraction disabled. The app window was fitted to the screen before these checks; this does not establish acceptance of all window sizes or display configurations.
- Read-only native probes confirmed that this Apple silicon Mac reports charge control supported, stored limit 100%, and limit disabled; the macOS 27 menu visibility interface matches the expected method signatures. These probes do not write battery settings or hide icons.

`Documentation/Verification.json` records the last accepted build/test checkpoint. Do not interpret an older checkpoint as validation of newer source files.

## Required hardware and permission acceptance

Use a signed build installed at a stable path. Grant only the permissions needed for the feature under test.

1. **Stack:** copy plain/RTF text, images, and multiple Finder URLs; verify all formats survive copy-back. Verify source icons and metadata. Copy concealed password-manager content and confirm it is omitted. Exercise FIFO shortcuts in TextEdit and Finder; cancel by disabling Stack during the focus delay. Quit and verify memory history resets.
2. **AirBridge:** route two playing apps to different devices, including Bluetooth. Listen for channel correctness, duplication, glitches, and restoration on Stop/Stop All/quit. Test dual-device mirroring, repeated start/stop, disconnect/reconnect, sample-rate changes, source app exits, and sleep/wake. Routes stop on sleep and need an explicit restart. Check CPU/latency with Instruments under sustained playback. Verify that meters and Aperture frequency bands follow audible output, become silent when input stops, and do not animate synthetic activity. Zero buffers from denied permissions must not be confused with audible routing success.
3. **Aperture/Shelf:** verify physical notch alignment on multiple MacBook models, menu-bar auto-hide, mirrored/scaled displays, external displays, full-screen apps, Spaces transitions, reduce-motion mode, overflowing clipboard text, file and text drags, cancelled drags, and outbound transfers. Verify a window title-bar drag after a file drag does not reuse a stale drag pasteboard to open the tray. For optional Now Playing, explicitly connect a running Music/Spotify player, accept or deny Automation, and verify track changes, local Music art, source-specific controls, revoked access, quit/relaunch, stalled player requests and cancellation. Enable Spotify artwork downloads separately and verify actual CDN artwork, disabled downloads, redirects and network failure. A routed unsupported app must never acquire an unrelated player's artwork. Without a connected selected player, media buttons use system media keys; verify the current media responder receives them. The spectrum comes only from an active AirBridge route. CoreAudio provides an app name, not universal song titles or artwork; the two native providers do not cover all apps.
4. **Grid/Border/Monolith/Menu Manager:** grant Accessibility and test active windows across vertically/horizontally offset displays, app minimum-size constraints, full-screen failures, rapid focus changes, accent changes, revoked access, desktop focus, and session expiry. Background panels must never intercept clicks or remain after stop. Menu collapse is opt-in: verify selected third-party icons disappear, system/Bezel icons remain, expanding restores all icons, the shelf opens an original menu after revealing it, and cancellation/timeout/access revocation/normal quit restores visibility. Test macOS 27's runtime-bound menu visibility interface separately from the older divider implementation.
5. **Scope/Finder:** enable Bezel Finder Actions in macOS extension settings and verify single-selection Analyze, Inspect Archive, Compress, and Extract context menus, URL launch when the host window is closed, Unicode/space filenames, transactional extraction to writable destinations, read-only errors, and cancellation. Verify the inspector's filter/table, partial-list notice, unsafe-entry warnings, and Extract action. Inspection creates no extracted files; enumeration stops at 20,000 headers or before advancing beyond 512 MB of declared entry data. Advancing through compressed tar entries may decompress preceding data. Additional encrypted/proprietary RAR/7z variants may be unsupported by the system library. Inspect a large directory under Instruments. APFS clone/hard-link sizes remain estimates.
6. **Lens:** grant Screen Recording; select/cancel on Retina and mixed-scale displays; verify coordinate mapping and line order for images, multi-column text, and video frames. Verify that app windows are excluded and protected content is handled without a bypass.
7. **Tether/Pulse:** verify real battery state on battery/AC changes, no-internal-battery hosts, disk/display assertions, countdown expiry, PID exit/reuse, short idle periods, thirty-second idle release, and cleanup on quit. On a compatible Apple silicon Mac running macOS 26.4 or later, record the existing enabled/limit state before explicitly testing Limit to 80%, temporary Top Off to 100%, and Remove Limit, then restore it. Verify observed behavior while connected to power, serialization of rapid requests, native error handling, quit during a write, and preservation of the stored cap during top-off. A returned setting does not prove physical charging behavior. The helper is runtime-bound to private PowerUI selectors, has no root/SMC access, and exposes only status/limit80/topOff100/removeLimit. Native macOS charging can occasionally reach 100% for calibration; it does not satisfy an absolute electronic ceiling.
8. **System behavior:** verify login item opt-in, closing/reopening the dashboard from the menu bar, shortcut conflicts, permission changes and restart instructions, idle CPU/wakeups, memory after heavy clipboard/image use, VoiceOver, light/dark appearance, and keyboard navigation.

## Focus workflow acceptance

Create two native Shortcuts workflows with distinct names: one uses Set Focus to turn Do Not Disturb on until turned off, and the other turns that same Focus off. Configure those names in Monolith and opt in to automation. Verify start, manual end, expiry, normal quit, a failed starting workflow, a failed ending workflow, and recovery on relaunch. Bezel reports whether the configured workflow finished; it cannot prove that an arbitrary user-selected workflow changed Focus. The ending workflow turns off the chosen Focus rather than restoring a different previously active Focus. Do not execute a user's workflows as part of a read-only probe.

## Distribution

Set your own application/extension bundle identifiers and Developer ID team in Xcode. Archive and sign the app, embedded extension, and charge-control executable using the same team. Keep the hardened runtime enabled for the distributed build. The checked Release app's signature contains the runtime flag; Xcode reports hardened runtime disabled for the local Debug ad-hoc build. Replace the local ad-hoc signatures with Developer ID signing, notarize using Apple's notary service, and staple the accepted ticket. Test the downloaded package on a clean Mac, including each private-interface compatibility check and failure path. No valid Developer ID signing identity, notarization account, update feed, installer, or release publication was supplied in this workspace.

## Incomplete original requirements

- **Monolith:** current dimming uses black overlay panels. It does not set another app's window alpha to exactly 10%. Automatic Do Not Disturb requires the configured and accepted native workflows above.
- **Aperture:** real FFT bands and opt-in native Music/Spotify metadata/artwork providers are implemented. Live player access, actual artwork and controls still require acceptance. Other players have no universal current-track/album-art provider.
- **Tether:** a compatible native charge-control helper is implemented, but its physical 80% cap/top-off behavior has not been accepted, and Apple's calibration behavior permits charges beyond the requested hard ceiling.
- **Menu Manager:** a native menu visibility implementation is present, but actual third-party icon concealment and restoration still require permission-dependent acceptance. Its private interface is not an Apple-supported SDK contract.
- **Production acceptance:** audible multi-app routing, OCR/Accessibility behavior, Finder enablement, notch/multi-display/drag behavior, performance, and distribution signing/notarization remain required gates. A compiling app or passing deterministic test suite cannot close those gates.
