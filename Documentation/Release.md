# Release acceptance

The project produces a universal macOS app with an embedded sandboxed FinderSync extension and an isolated charge-control executable. Local build success and deterministic tests do not establish full production acceptance. Preserve the original eleven-module requirements when evaluating this checklist.

## Required hardware and permission acceptance

Use a signed build installed at a stable path. Grant only the permissions needed for the feature under test.

1. **Stack:** copy plain/RTF text, images, and multiple Finder URLs; verify all formats survive copy-back. Verify source icons and metadata. Copy concealed password-manager content and confirm it is omitted. Exercise ⇧⌘C copy-and-open and ⇧⌘V selected-paste in TextEdit and Finder; click a non-head clip and verify it pastes into the original text field immediately, preserving remaining order/history. Hold and release the shortcut modifiers, switch app focus during the handoff, revoke Accessibility, and cancel; failed/canceled commands must not post keys or consume a clip. Click clips in copy mode and verify the system clipboard contents. Verify search, multi-selection, Delete Selected, Delete All, and clearing during a pending copy; cancel by disabling Stack during the focus delay. Quit and verify memory history resets.
2. **AirBridge:** route two playing apps to different devices, including Bluetooth. Listen for channel correctness, duplication, glitches, and restoration on Stop/Stop All/quit. Test dual-device mirroring, repeated start/stop, disconnect/reconnect, sample-rate changes, source app exits, and sleep/wake. Routes stop on sleep and need an explicit restart. Check CPU/latency with Instruments under sustained playback. Verify that meters and Aperture frequency bands follow audible output, become silent when input stops, and do not animate synthetic activity. Zero buffers from denied permissions must not be confused with audible routing success.
3. **Aperture/Shelf:** verify physical notch alignment on multiple MacBook models, menu-bar auto-hide, mirrored/scaled displays, external displays, full-screen apps, Spaces transitions, reduce-motion mode, overflowing clipboard text, file and text drags, cancelled drags, and outbound transfers. Verify smooth opening/closing without native-window clipping, configurable moment timing, hover-to-hold and Reduce Motion. Move/resize Shelf through the header, grip, presets, and dashboard sliders; check remembered placement after display removal. Capture an image directly into Shelf, paste an image from the clipboard, preview through Quick Look, export it, and verify clearing/quit removes only the temporary captures. Grant or deny Focus status access in Aperture; toggle Control Center Focus with macOS sharing enabled and verify on/off banners, no repeats, revoked sharing remaining unknown, and no claim of a particular Focus name. Verify a window title-bar drag after a file drag does not reuse a stale drag pasteboard to open the tray. For optional Now Playing, explicitly connect a running Music/Spotify player, accept or deny Automation, and verify track changes, local Music art, source-specific controls, revoked access, quit/relaunch, stalled player requests and cancellation. Enable Spotify artwork downloads separately and verify actual CDN artwork, disabled downloads, redirects and network failure. A routed unsupported app must never acquire an unrelated player's artwork. Without a connected selected player, media buttons use system media keys; verify the current media responder receives them. The spectrum comes only from an active AirBridge route. CoreAudio provides an app name, not universal song titles or artwork; the two native providers do not cover all apps.
4. **Grid/Border/Monolith/Menu Manager:** grant Accessibility and test active windows across vertically/horizontally offset displays, app minimum-size constraints, full-screen failures, rapid focus changes, accent changes, revoked access, desktop focus, and session expiry. Background panels must never intercept clicks or remain after stop. Menu collapse is opt-in: verify selected third-party icons disappear, system/Bezel icons remain, expanding restores all icons, the shelf opens an original menu after revealing it, and cancellation/timeout/access revocation/normal quit restores visibility. Test macOS 27's runtime-bound menu visibility interface separately from the older divider implementation.
5. **Scope/Finder:** enable Bezel Finder Actions in macOS extension settings and verify single-selection Analyze, Inspect Archive, Compress, and Extract context menus, URL launch when the host window is closed, Unicode/space filenames, transactional extraction to writable destinations, read-only errors, and cancellation. Verify the inspector's filter/table, partial-list notice, unsafe-entry warnings, and Extract action. Inspection creates no extracted files; enumeration stops at 20,000 headers or before advancing beyond 512 MB of declared entry data. Advancing through compressed tar entries may decompress preceding data. Additional encrypted/proprietary RAR/7z variants may be unsupported by the system library. Inspect a large directory under Instruments. APFS clone/hard-link sizes remain estimates.
6. **Lens:** open the dashboard at 900×600 and 1120×780 in light/dark appearance; verify title bar/sidebar stay on screen and controls scroll rather than displacing the window. Grant Screen Recording to the exact running build shown in Lens, quit/reopen that same build, and test both the button and shortcut. Verify immediate progress/error feedback beside Capture Text, content/screenshot deadlines, canceled and late replies, revoked access, and a permission grant made while the app is running. Set up stable Apple Development signing for Debug to test permission persistence across rebuilds; the local ad-hoc build cannot guarantee that persistence. Then select/cancel on Retina and mixed-scale displays; verify coordinate mapping and line order for images, multi-column text, and video frames. Verify that app windows are excluded and protected content is handled without a bypass.
7. **Tether/Pulse:** verify real battery state on battery/AC changes, no-internal-battery hosts, disk/display assertions, countdown expiry, PID exit/reuse, short idle periods, thirty-second idle release, and cleanup on quit. On a compatible Apple silicon Mac running macOS 26.4 or later, record the existing enabled/limit state before explicitly testing Limit to 80%, temporary Top Off to 100%, and Remove Limit, then restore it. Verify observed behavior while connected to power, serialization of rapid requests, native error handling, quit during a write, and preservation of the stored cap during top-off. A returned setting does not prove physical charging behavior. The helper is runtime-bound to private PowerUI selectors, has no root/SMC access, and exposes only status/limit80/topOff100/removeLimit. Native macOS charging can occasionally reach 100% for calibration; it does not satisfy an absolute electronic ceiling.
8. **System behavior:** verify login item opt-in, closing/reopening the dashboard from the menu bar, shortcut conflicts, permission changes and restart instructions, idle CPU/wakeups, memory after heavy clipboard/image use, VoiceOver, light/dark appearance, and keyboard navigation.

## Focus workflow acceptance

Create two native Shortcuts workflows with distinct names: one uses Set Focus to turn Do Not Disturb on until turned off, and the other turns that same Focus off. Configure those names in Monolith and opt in to automation. Verify start, manual end, expiry, normal quit, a failed starting workflow, a failed ending workflow, and recovery on relaunch. Bezel reports whether the configured workflow finished; it cannot prove that an arbitrary user-selected workflow changed Focus. The ending workflow turns off the chosen Focus rather than restoring a different previously active Focus. Do not execute a user's workflows as part of a read-only probe.

## Distribution

Set your own application/extension bundle identifiers and Developer ID team in Xcode. Archive and sign the app, embedded extension, and charge-control executable using the same team. Keep the hardened runtime enabled for the distributed build. The checked Release app's signature contains the runtime flag; Xcode reports hardened runtime disabled for the local Debug ad-hoc build. Replace the local ad-hoc signatures with Developer ID signing, notarize using Apple's notary service, and staple the accepted ticket. Test the downloaded package on a clean Mac, including each private-interface compatibility check and failure path. `Scripts/build-release.sh` defaults to Apple Development signing for local builds. For distribution, set `BEZEL_SIGNING_IDENTITY` to a Developer ID Application certificate and `BEZEL_DEVELOPMENT_TEAM` to its team. For the signed image, `Scripts/package-release.sh` also requires `BEZEL_NOTARY_PROFILE` naming an existing Keychain profile. Its default mode submits the image to Apple; run it only when ready for that submission. It verifies Developer ID, team, hardened runtime and timestamp for both architectures of the host and embedded code, packages an Applications shortcut, signs the image, checks the JSON notarization status, staples and validates the ticket, and assesses Gatekeeper before replacing the final image. A rejected or timed-out submission preserves its response at `Build/Notarization.json` and retains any prior final image. This follows Apple's [packaging](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution) and [notarization](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow) workflows.

`Scripts/package-release.sh --development` instead creates `Build/Bezel-Development.dmg` locally without notarization or signing the image. Its embedded app retains the selected archive's signing identity (currently Apple Development). It is a development artifact, not a distribution-accepted installer. No valid Developer ID signing identity, notarization account, update feed, clean-Mac installation acceptance, or release publication was supplied in this workspace.

## Incomplete original requirements

- **Monolith:** current dimming uses black overlay panels. It does not set another app's window alpha to exactly 10%. Automatic Do Not Disturb requires the configured and accepted native workflows above.
- **Aperture:** real FFT bands and opt-in native Music/Spotify metadata/artwork providers are implemented. Live player access, actual artwork and controls still require acceptance. Other players have no universal current-track/album-art provider.
- **Tether:** a compatible native charge-control helper is implemented, but its physical 80% cap/top-off behavior has not been accepted, and Apple's calibration behavior permits charges beyond the requested hard ceiling.
- **Menu Manager:** a native menu visibility implementation is present, but actual third-party icon concealment and restoration still require permission-dependent acceptance. Its private interface is not an Apple-supported SDK contract.
- **Production acceptance:** audible multi-app routing, OCR/Accessibility behavior, Finder enablement, notch/multi-display/drag behavior, performance, and distribution signing/notarization remain required gates. A compiling app or passing deterministic test suite cannot close those gates.

## Accessibility repair build

Window control now checks actual external-window access when the trust preflight reports denied, with a 150 ms AX messaging limit. An unresponsive app is never accepted as proof of access. Keyboard commands use their own CoreGraphics event-post permission instead of combining it with a possibly stale AX flag. Setup shows these capabilities separately, can explicitly request both public permissions, and refreshes every two seconds while Bezel runs. No privacy records are changed by Bezel.

`Scripts/build-release.sh` refuses to overwrite an archive whose Bezel executable is running. Set `BEZEL_ARCHIVE_PATH` to an alternative archive for an update; packaging accepts the same variable. The initial Accessibility repair was built into `Build/Bezel-Accessibility.xcarchive`; the final signed repair is `Build/Bezel-Signed.xcarchive`. Earlier archives are preserved under `Build/Previous.noindex`; current build and package defaults use `Build/Bezel-Signed.xcarchive`. Quit the old app normally before opening the updated app; clipboard history is memory-only.

```sh

BEZEL_DEVELOPMENT_TEAM='YOURTEAMID' \
BEZEL_ARCHIVE_PATH="$PWD/Build/Bezel-Signed.xcarchive" \
```

Use the real values from your own Xcode signing account. After the owner added their Xcode account, automatic provisioning created an Apple Development certificate.
