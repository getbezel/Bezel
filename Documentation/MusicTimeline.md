# Aperture track timeline

Expand the Now Playing capsule to drag the track-position slider. The left label shows elapsed time; the right shows remaining time. Keyboard/assistive adjustments move by five seconds. The native slider supports pointer dragging and clicks. The player panel and fixed hosting canvas have been enlarged to contain the timeline alongside artwork, transport controls and volume.

Timing comes from a connected Apple Music or Spotify process's scripting interface. Position is seconds for both players; Apple Music track duration is seconds and Spotify's raw duration value is normalized from milliseconds. The existing two-second metadata poll now also refreshes position/duration, including cached-track replies. Between polls, the expanded view projects elapsed time using a monotonic clock at up to four updates a second. It stops projecting while paused or during a drag, and uses a slower cadence with Reduce Motion.

A scrub captures the player instance and track ID at the start. UI, metadata routing, reader cache and native bridge validate these identities before applying a seek. The native bridge rereads the actual track identity and duration before setting player position. Nonfinite values, unavailable/zero duration, closed players, unsupported sources and known Spotify advertisement identifiers are rejected. A source without timing information displays “Timeline unavailable for this source.” Failures restore reported player timing on refresh and show a control error; they do not fall back to controlling another player.
